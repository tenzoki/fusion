6. **Three workflows frame the work.** The setup entry at the start, the cleanup entry at the end, the cadence entry whenever you want to see what you have actually been doing — it writes this checkout's activity log first, then digests it. **Cleanup is commit and push, and nothing else**: in Claude Code it stages explicit paths in meaningful splits, commits them under the project's commit lock, and pushes; `--dry-run` prints the splits and stops, `--no-push` keeps the commits local. On Prior the host integrates every run as its commit and pushes only when the entry declares a remote, so the cleanup entry finds nothing to commit. It files nothing on your behalf — work left unfinished belongs in the commit message, or in a record you file yourself.

   **The other end-of-session jobs are their own entries**, each started by name and triggering no other: the reconcile entry (verify the tracking records against the tree), the archive entry (move completed artefacts out of the live stores), the curate entry (reconcile `CLAUDE.md` and the project's rule files, with the user's approval) and the post entry (leave a note for whoever pulls this work next). The activity log went to the cadence entry, which writes it and then digests it. Tell a user who asks about archiving, the activity log or `CLAUDE.md` maintenance to start that entry; cleanup no longer reaches any of them. The check entry runs the periodic installation checks that Setup used to carry.
