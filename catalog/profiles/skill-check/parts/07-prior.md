**Read what the cache costs here before you rely on this.** It is the one check whose subject is a session, and an entry run is none: on Prior it reports whether an orchestrator session's marker is live and writes no marker of its own. A run inside the 30-day window at an unchanged plugin version never runs it, so the collision warning is not reached. That was chosen with the rest of the ramp-up cut. Start the check entry with `--only concurrency` whenever a second session is plausible. The workspace carries the checkout's `.session-marker`, so on Prior the check reads the marker a live session on this checkout left, as it does on Claude Code (request 77, question 5).
