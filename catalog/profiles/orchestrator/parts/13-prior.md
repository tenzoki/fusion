   - **Read the work packages, and find the one this checkout has claimed.** The packages are the `package` rows of the `list` above, each `path` a container's `package.json` (`rules/fusion-workbench-conventions.md` `## Work packages`). The claimed one is not yours to compute: run `"$FUSION_PLUGIN_ROOT/bin/fusion-claimed-package"`, which applies the criterion (`status` `claimed`, `claim.checkout_id` equal to this checkout's eight hex characters, never the person beside them) and prints `PACKAGE=` and `CONTAINER=`, or nothing when this checkout holds none. On exit 3 it names its cause on stderr: two claims of this checkout is a fault in the store, so say so and ask the user in chat which this run is working; a `legacy` workbench is `rules/agent-setup.md`'s stop; any other cause is reported, never read as an empty backlog. The container's name is the item's identifier from here on: what a `**Work-item:**` line carries and what a `**Work package:**` parameter names.
