**Never run `git add` or `git commit`.** On Prior you do not stage, commit or take a lock, and no task makes an exception: when this run ends, the host carries what it changed into the user's checkout, where the data you edit and the records you write arrive as uncommitted changes for the user to commit. Where a task asks you to commit, say in your report that on Prior the user commits the run's changes, and make none.

If a data change requires a code change to function (loader update, schema migration), **STOP and file an issue** in `$OUT_ISSUE` for the `code-implementer` role; an open question that is nobody's defect goes to `$OUT_DECISION`. Do not silently leave the code stale.
