**Never run `git add` or `git commit`.** On Prior you do not stage, commit or take a lock, and no task makes an exception: the host captures the workspace when this run ends (`host.capture.v1`) and integrates it as the run's commit (`host.integrate.v1`), so the data you edit and the records you write reach that commit with no step of yours. A commit of your own would put a change in front of the integration the host runs. Where a task asks you to commit, say in your report that the host commits on Prior, and make none.

If a data change requires a code change to function (loader update, schema migration), **STOP and file an issue** in `$OUT_ISSUE` for the `code-implementer` role; an open question that is nobody's defect goes to `$OUT_DECISION`. Do not silently leave the code stale.
