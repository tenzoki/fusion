1. **Write the message to a file first.** Use the `Write` tool, or a **quoted** heredoc delimiter (`cat > "$MSG" <<'FUSION_MSG_EOF'`) — never a bare `<<EOF`, which still expands `$var` and runs backticks inside the message body.

   The file goes at `~/.fusion-tmp/<checkout-id>/fusion-commit-msg-<session-id>-<n>.txt`, written absolute, in the directory `"$FUSION_PLUGIN_ROOT/bin/fusion-tmp" path` prints once per run (stop if it fails), where `<session-id>` is the Claude Code session identifier SessionStart printed in front of you as `fusion: session_id=<id>` and `<n>` numbers the splits of this run. **Never inside `fusion-workbench/`**: that tree is the one `git status` reports on, so a message file left there becomes an untracked artefact the next run has to explain. Two sessions in one checkout share the directory, which is why the session identifier is in the name. If SessionStart printed no identifier, use the `CHECKOUT=` value from `"$FUSION_PLUGIN_ROOT/bin/fusion-identity"` in its place and say so in the report: two sessions on one checkout then share the file.
