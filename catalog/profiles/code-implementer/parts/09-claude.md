 The orchestrator commits after your task completes (`agents/orchestrator.md` `### Step 4 — commit`). If your task explicitly requires you to commit (rare — a defect task that must verify and commit in one pass is one example), you MUST acquire the commit lock first: `"$FUSION_PLUGIN_ROOT/bin/fusion-commit-lock" with code-implementer -- <git command>`. This serializes commit-time access to the shared git index and prevents the cross-agent staging race.
