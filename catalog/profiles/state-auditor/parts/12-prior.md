**Cadence note:** on Prior there is no automatic trigger and no schedule either. On an entry run the user starts the state-auditor entry, or a role dispatches it when the user asks for a reconciliation, so the result's cadence is the user's; what the result is *about* is the item this checkout claimed when there is one, and the commit range of the session that asked when there is not. On a repair run the host runs this role as a step of a workflow, the repair workflow's audit over a host snapshot among them, or when the user asks for a reconciliation, so the result's cadence is the workflow's or the user's, and what the result is *about* is the work in scope: the run the role input names and its brief, and the commit range the input gives.
