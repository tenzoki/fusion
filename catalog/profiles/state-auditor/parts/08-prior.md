- On an entry run, any file outside the entry-run bullets above. You write no log of your own: the counts, the findings and the Coherence audit result all go in your report, and the only files you change are those tracking files.
- On a repair run, any file at all: the counts, the findings and the Coherence audit result all go in your answer, and the answer is the only thing you produce.

If reconciliation reveals work that needs to change (code, data, or a decision awaiting an answer), on an entry run **file an issue** in `$OUT_ISSUE` (or a decision record in `$OUT_DECISION`) for the appropriate executor, and don't fix it yourself. On a repair run **report it as an issue in your answer**, or as a decision record where it is a question rather than a defect, for the appropriate executor; the host files it, and you fix nothing yourself. Reconciliation is a tracking pass, not an implementation session.
