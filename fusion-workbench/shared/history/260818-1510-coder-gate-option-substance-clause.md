# Gate options must state substance, not category

**Status:** Complete
**Agent:** coder
**Date:** 260818
**Source record:** `260818-1452_*_gate-options-name-the-category-of-what-is-being-decided-instead-of-stating-its-content.md`

## What was implemented

One clause added to `rules/user-facing-output.md` `## Questions and gates`, placed directly after
the plain-English-options clause and well ahead of the foreclosure clause at the section's end.
It requires that a gate option state the substance of what it decides rather than its type, and
it is demonstrated with the real failing instance rather than an invented one, matching how every
other clause in that section is written.

Two readings the clause forecloses in its own text, because either would have made it useless:
it is not an instruction to write longer options (the same section caps `AskUserQuestion` option
labels at four lines, and the substantive form is usually the same length as the category form),
and it is not the foreclosure clause restated (that one says what a choice rules out; an option
can state that perfectly while staying abstract about its own subject, which is exactly what the
reported gate did).
