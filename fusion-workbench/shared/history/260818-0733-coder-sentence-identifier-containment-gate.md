## What was built

`hooks/lib/__tests__/sentence-identifier-containment.test.ts`, 273 lines. It calls
`coverageSentence()` and `stagingSentence()` directly on synthetic reports and asserts
`identifiers(builder(input)) ⊆ identifiers(input)` — every identifier in the emitted string must
have entered through that call's input.

Identifier extraction is two classes: the `YYMMDD-HHMM` record stamp and a 7-to-40 character git
object name. Record paths and Circle directory names carry a stamp by the naming convention, so
they need no class of their own. A hex token with no digit is excluded, so that English words
spelled in hex ("defaced") are not read as commits; that costs about 1 in 700 short hashes and is
stated in the file header rather than left to be discovered.

Nine branch cases, which is every branch of both builders:

| Builder | Branches driven |
|---|---|
| `coverageSentence` | empty (silent), uncovered, carried without `carriedFrom`, carried with `carriedFrom`, uncovered + carried |
| `stagingSentence` | no faults (silent), records (an untracked and an unstaged row), commit-message, records + commit-message |

The two silent branches are pinned to `""` rather than skipped. Two further cases pin the gate's
own behaviour: sensitivity, against a stamp injected beside a true measurement, and specificity,
against the branch that emits four of the consuming project's own hashes and must stay green — the
branch on which the rejected shape-blacklist design fails.

The registry-completeness assertion parses `hooks/tracker.ts`'s import blocks for `*Sentence`
symbols and requires the set to equal the registry's keys, so a third builder wired into the funnel
fails the suite until it is registered.
