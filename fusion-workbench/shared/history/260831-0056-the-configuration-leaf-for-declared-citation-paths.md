## What changed

Four hand-edited files and the regenerated build. Nothing reads the new leaf
yet: step 2 is what gives it a reader.

**`hooks/lib/config.ts`.** `citations.extraPaths` was added to `GuardSettings`,
to `RawConfig`, to `DEFAULTS` with `[]` as its value, to `CONTAINER_LEAF_RULES`
with `expected: "an array of strings"`, and to the leaf walk in `loadConfig`
through a `pickCitations` helper shaped exactly like `pickOrchestrator`.

The check is one predicate over the array **and** its elements,
`isArrayOfNonEmptyStrings`. A value that is not an array, or an array holding a
non-string or an empty string, fails it once, so the leaf is dropped whole,
named in a single diagnostic, and then inherits exactly as an omitted key does
— the per-leaf equivalence
`260804-1630_*_what-does-a-project-guard-object-inherit-for-a-key-it-does-not-supply.md`
mandates. An explicit `[]` passes the check and survives as itself.

The empty string is refused with the non-strings, and the reason is measured
rather than assumed: `git ls-files -- ':(glob)'` with an empty pattern lists
every tracked file in this repository, so an empty element is the one wrong
value a resolver would read as a very wide right one. The measurement is
recorded in the function's own docstring.

Nothing here validates a pattern's *shape*. Whether a pattern is absolute,
carries a `..` segment, or names any file at all is decidable only where the
patterns are resolved, and the docstring says so in those words so that step 2
does not find the question answered twice.

**The cardinality claims.** `## The one leaf` became `## The settings` and now
describes both settings in turn, naming each rather than counting them
(`rules/critical-stance.md` §5). Four further sentences stated the count and
were corrected: the docstring's opening paragraph (which now says every default
is defined once in `DEFAULTS` rather than that there is one), the sentence
saying the walk was kept as a shape "because the next setting to land here
inherits the rule" (`citations.extraPaths` is that setting, and the sentence
now says so in the past tense), the `diagnostics` field's "with a single leaf to
resolve", and the `RETIRED_PROJECT_FILES` advisory's "The one setting it
carried", where the numeral was simply dropped: the setting is named in the
same clause, so nothing was lost. The advisory's migration text is otherwise
untouched, and `config.test.ts` still holds it phrase by phrase.

**`templates/fusion.json` and `fusion.json`** received the identical
`_citations` note, inserted after `_turnBudget` in both, plus the two sentences
that stated the old count: `_what`'s "configures exactly one thing" and

The note says what the key means, that an entry is a git pathspec read under
`:(glob)`, and that declaring nothing leaves today's behaviour exactly as it is.
It deliberately does **not** describe the refusal and unmatched-pattern
reporting that step 2 builds: at this commit nothing resolves a pattern, and a
shipped template that described a mechanism the release does not carry would be
the silent-wrongness the rest of that file exists to prevent. What it does carry
is the judgement the declaration is: outside Markdown there is no fence and no
block quote, so a project declaring a file that merely *exhibits* record names
will have every such token reported as a pointer.
