## The one judgement the step's text did not fit, and where it went instead

The step asks for the "deliberately not declared" clause about the test
fixtures to go in `fusion.json`'s top-level `_citations` note. That note cannot
carry it. The drift check compares every byte of both files outside the
top-level entries named in `PROJECT_SET_KEYS`, and it opens with an
anti-vacuity assertion that the cut is a **no-op on the template**. So adding
`_citations` to `PROJECT_SET_KEYS` fails that assertion (the template carries
the note), and editing the note without adding the key fails the byte
comparison. Three of the step's constraints — the template untouched, the note
edited, `PROJECT_SET_KEYS` gaining `citations` — cannot all hold.

The clause went into a `_note` key **inside** the `citations` object, where the
cut carries it out of the comparison with the entry it belongs to. The loader
keeps an unrecognised key inside a known container without a diagnostic
(`hooks/lib/config.ts`, the `rule === undefined` branch of the leaf walk), so
this is the same silence every underscore-prefixed note in the file already
gets, and it sits next to the declaration it qualifies rather than a screen
away from it. The note states the exclusion, carries the measurement, and says
why it lives there.
