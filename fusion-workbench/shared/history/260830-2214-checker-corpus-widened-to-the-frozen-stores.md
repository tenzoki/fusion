## Why

The rewriter's corpus was strictly wider than the reporter's, so the sweep
changed files this checker then declared clean. That is the defect. The four
measurements, each taken rather than argued:

1. This repository swept its own archive in `f1099c5f`, 565 files. Whatever the
   rewriting-history position was, it had already been overridden in practice
   for the sweep, by this project, without anyone stating it.
2. `workbenchIndex()` walks the whole workbench with no prefix filter, and
   `circleDirs()` carries an explicit `archive/<sweep>/circles` branch whose
   comment reads "a bare directory name resolves wherever the directory is". The
   frozen stores were in-corpus for resolution and out-of-corpus for reporting,
   in one file.
3. A store-prefixed citation inside an archived record is already dead: the
   three store-prefixed patterns are detectors, matched and never resolved.
   Rewriting one to the storeless form makes it resolve again. For that class
   the rewrite restores a pointer instead of falsifying a record.
4. A consuming project's `.migration-v2-backup/` holds 0 store-prefixed
   citations across its 205 files, so the exception this was expected to need
   has no measured case.

The gate is a different instrument and keeps its exclusions. It reddens the
suite of somebody who compiled nothing, over text an archive sweep moved; a
reporter costs its reader one row.
