## What changed

One hand-edited source file, one test file, the regenerated build and the issue
record.

**`hooks/citation-sweep.ts`.** The per-`extra`-path loop in `refusal()` already
resolved each argument and refused one outside the work tree. It now also asks
`git ls-files --error-unmatch` of each surviving argument, which is the question
the guard asks about the workbench eleven lines earlier, and collects the ones
git does not track. A non-empty collection returns one refusal line,
`refused (path-untracked)`, naming up to ten paths and counting the rest the way
the dirty-tree refusal already does, at exit 4. The outside-the-work-tree branch
keeps returning on the first offender, so an argument that is outside is named
as outside rather than as untracked. An argument that resolves to the work-tree
root is asked about as `.`, the same substitution the workbench check makes for
an empty relative path.

No new guard, no new call site, and the declared corpus is untouched:
`git ls-files` cannot name an untracked or ignored file, so the route step 2
built is tracked by construction and only a hand-passed `<path>` reaches this
branch. Saying that in the header was the alternative to a redundant check, and
it is what the plan asked for.

**The header.** Guard (a)'s block now states the extra-path condition as
"inside that same work tree **and** be tracked by it", names the mechanism, and
carries the measurement as its reason: on 2026-08-31 a real run was pointed at
89 code files in a consuming project, 79 tracked and 10 under a gitignored
build-output directory; all 89 were rewritten and the 10 have no committed
version to return to. Harmless there because build output is regenerated,
harmless by luck rather than by construction. The block also states two things
the code alone leaves to be inferred: a `<path>` naming a directory is asked
exactly the question the workbench is asked and keeps the same residual (a
directory holding anything git tracks passes, and an untracked file beneath it
is still rewritten), and the check is per argument and never widens to the whole
work tree, because a project may legitimately leave its workbench untracked.
The exit-code table's line for 4 gained "or untracked by it".

**`hooks/lib/__tests__/citation-sweep.test.ts`.** One case, 29 inserted lines
against the 40 the plan allowed. A scratch repository with a committed tree, a
tracked `kept.go` and a gitignored `ignored.go`: `--write --yes ignored.go`
exits 4 with the exact refusal line and leaves the file byte-identical;
`--write --yes kept.go` reaches the write and rewrites the citation, so the
branch is shown to refuse the untracked case alone rather than the argument
route as such.
