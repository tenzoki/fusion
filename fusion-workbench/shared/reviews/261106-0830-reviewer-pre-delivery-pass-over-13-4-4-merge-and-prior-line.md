#### What undoes an integrated migration on Prior

Nothing fusion ships. Git in the user's checkout does, and the text must promise that and no more.

| Moment | What undoes it | Basis |
|---|---|---|
| Before the run ends | `bin/fusion-migrate rollback`, in the same container | measured: exit 0, `result=legacy` |
| Integrated, not committed | `git restore --staged --worktree -- fusion-workbench`, then deleting the added paths the integration lists | measured with `git clean`, which also deleted a file untracked before the run |
| Integrated, committed | `git revert` | measured; a later `run` works |
| Workbench not tracked | nothing but `archive/migrations/<id>/originals/`, converted records only | inference from the measured contents of `originals/` |

A later `run` is not blocked by the leftover `.json-state/` once the move finished (measured). Edits uncommitted at the start are lost to git's undo; a converted record's prior bytes are in `originals/`, which that undo removes too (measured).
