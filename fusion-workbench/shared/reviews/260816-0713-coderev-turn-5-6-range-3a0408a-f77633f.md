### Theme 3 — `skills/next/SKILL.md`'s `awk` pass (1 Low)

Measured with the shipped command on seven fixtures and against all fifteen `*circle.md` records in
this workbench. The three-way branch is correct in every shape I could construct: field present in the
head block → exit 0 and one written line; no field anywhere, field only after the first heading, empty
file → exit 9 and the note; a read or redirect failure → the `*)` branch. `.tmp` is removed on every
non-zero path, and the `mv` failure is reported rather than swallowed. A Status line that is the last
line of a file with no trailing newline is handled, and gains a newline.

Two residuals, both filed as `0723`: the head-block bound is `^## ` literally, so a record with no
heading (or one whose first heading is `# ` or `### `) leaves the whole file as the head block — what
actually protects a quoted template line there is the `!n` first-match guard, not the bound the prose
names; and on a CRLF record the rewritten line alone loses its CR. Neither is reachable from real
input: all fifteen records carry `**Status:**` at line 5 and their first `## ` at line 12-14. The
commit message says this; the skill body does not, and the skill body is what a reader gets.

### Theme 4 — `bin/monitor`'s token walk (1 Low)

The narrowing is correct and does what its record claims. Traced by hand against the shipped launch
form (`bin/monitor:1478`, `python3 "$TMPFILE" …`), so a monitor started by the wrapper always has the
script at argv[1] and is matched. `python3 -c` returns False (documented). An unreadable or empty `ps`
returns False. A browser command line returns False on the basename compare, which is the defect the
narrowing was for.

`0722` (Low): `env python3 <script>` also returns False — the loop returns on the **first** non-option
token, which is `python3`. It is the same class as the two residuals the docstring names (loses a
kill, never gains a wrong one, listener kill untouched) and it is not among them, while the docstring
presents its list as complete.

### Theme 6 — the citation gate's exact pin (1 Medium)

`68d6838` replaced three floors with `BASELINE = { paths: 1122, anchors: 139, records: 95 }` under
`toEqual`. The reasoning is sound and the failure message is unusually good. `0725` (Medium) names the
coupling nobody budgeted: `records` counts citations resolved against the **workbench**, and
`/fusion:cleanup`'s archive step rewrites the workbench. `findRecord` matches a `shared/`-prefixed
citation with an exact `shared/<store>` prefix, `workbenchIndex()` walks `archive/` too, and shipped
text carries such citations (`CLAUDE.md` names two). So archiving a cited record should both dangle
the citation and move the pin — **inferred from the two code paths, not measured**, because measuring
it means running the archive step. If it holds, this session's own cleanup can turn `npm test` red for
a reason that is not a text edit, and `BASELINE_MESSAGE` will tell whoever meets it to re-approve.
