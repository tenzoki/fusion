The record-example exemption silences a verdict that does not depend on resolution
---
`RECORD_EXAMPLE_FILES` exempts a whole file from every citation verdict. Its stated reason is that the file's records are fabricated, which is an argument about resolution: a made-up record cannot be found on disk. The `store-prefixed` verdict does not depend on resolution at all, and the exemption silences it anyway. The result is that the one file whose job is to teach the citation form is a file where a wrong form cannot be detected.
---
**Filed by:** consultant, Kai Stalmann <ks@qantr.com>

**Evidence.** `hooks/lib/citation-scan.ts:212` defines `RECORD_EXAMPLE_FILES` with the reason "the worked-example corpus — every record it walks is fabricated by design". `:563` computes `fileExempt` once per file and `:574` places it ahead of every other branch in the exemption chain, so no token in a listed file reaches a verdict. Two files are listed: `rules/decision-record-examples.md` and `skills/migrate/SKILL.md`.

`store-prefixed` is assigned at `:618`–`:632` from the shape of the token alone, before any lookup. A fabricated record and a real one are indistinguishable to it, which is exactly why the exemption's premise does not reach it.

**The defect this hid.** Until 2026-09-05 the `Answered:` footer under `rules/decision-record-examples.md` `## Example 1: Happy path: _o_ → _a_ → _i_` spelled its analyst report behind an `analyses/` store segment. It was filed as `260905-1228_*_the-worked-example-teaches-a-store-prefixed-citation-and-a-section-suffix-the-rule-rejects.md` and repaired there; the segment is gone from that footer and the token is not spelled here, because spelling it would delete this finding the same way. The hole that hid it is what this record is about, and it outlived the one token: a wrong form written into that file is still invisible.

**A narrowing alone does not fix that line.** The same token is covered independently by the fenced-code exemption at `:579`, and the example lives in a fence by necessity. Whoever repairs this decides both together or the change buys nothing: either the fence exemption yields to a shape-only verdict, or the teaching example moves out of a fence, or the store-prefix check runs on a pass that no file-level exemption gates.

**What must not happen.** `hooks/lib/__tests__/workbench-citation-lint.test.ts:213` already carries the warning that adding a file to `RECORD_EXAMPLE_FILES` is not the answer to a failing gate. This issue asks for the opposite move and inherits that caution: narrowing must not widen the silence anywhere else.

**Acceptance.** A store-prefixed token written into `rules/decision-record-examples.md`, inside its fenced examples, is reported by `npm test`. The two files' fabricated record citations continue to pass, and the pinned counts in `hooks/lib/__tests__/reference-resolution-lint.test.ts` are re-approved in the same commit if the change moves them.

Resolved: route 3, with the exemptions split by the premise each one rests on. `hooks/lib/citation-scan.ts` gains `SHAPE_DECIDED_KINDS` (`record`, `circle-record`, `circle-dir` — the three whose `check()` reads nothing off disk) and `RESOLUTION_PREMISED_EXEMPTIONS` (`record-example-file`, `fenced-code`). A token of a shape-decided kind under one of those two is now JUDGED and keeps its exemption reason, and the reason rather than the status is what `hooks/citation-sweep.ts` reads: the gate reports the retired spelling to a human, and nothing rewrites a verbatim exhibit. `skills/migrate/SKILL.md` moved out of `RECORD_EXAMPLE_FILES` into a new `RETIRED_LAYOUT_FILES`, which keeps full cover because its premise is about shape rather than resolution — the store segment is what that skill converts, and `CLAUDE.md` already calls it the only consumer allowed to name both layouts literally. The two store-prefixed prose citations left in `rules/decision-record-examples.md` `## Example 1: Happy path: _o_ → _a_ → _i_` and `## Example 2: Supersession: _i_ → _s_` are repaired to the storeless form with the store named in words; the file's fabricated basenames stay exempt, which is what the exemption is legitimately for.

Route 1 was rejected on measurement, not taste. Un-silencing the fence outright reaches the sweep, which shares this grammar and walks the whole workbench: `bin/fusion-citation-sweep --dry-run` went to `files=64 rewrites=370`, most of it inside `archive/` and inside fenced exhibits whose whole content is a wrong spelling somebody filed on purpose. Rewriting those deletes the findings. Route 2 was rejected for two reasons: the worked examples are decision-record bodies, so un-fencing them lets their own `---` and headings render as this file's structure, and it fixes one file while the next teaching file with a fenced example reopens the hole.

The narrowing costs nothing anywhere else, measured before it was written: over the shipped markdown surface the only store-shaped exempt tokens were the six in these two files, and over the live workbench corpus there were none under either narrowed exemption (29 `glob` and 1 `blockquote`, both of which keep full cover). The same argument reaches `announced-illustration`, `footer-template` and `fabricated-name`; each measured zero store-shaped tokens over both corpora, each has fixtures that would have to be rewritten to decide it, and this record names none of them, so they were left alone and the residual is written into `SHAPE_DECIDED_KINDS`.

The acceptance is a test and was also run against the real file: `hooks/lib/__tests__/fenced-code-exemption.test.ts` gains three cases (judged inside a fence, judged inside the worked-example file's fences, still exempt inside the layout-conversion file), and re-introducing the exact token this record was filed about, inside Example 1's fence, turns `npm test` red and names it. `hooks/lib/__tests__/workbench-citation-lint.test.ts` gained the one verdict the fence does not cover to its failure message. This record's own line 11 was rewritten first: it spelled that token inline while making a statement about it, which failed both citation gates, and it now names the file and the heading and says the segment in words.

One golden is left stale for the committing step rather than regenerated: `fixtures/rules-emission.golden` was already red from the sibling repair of the same file, and this change adds -11 bytes to `decision-record-examples.md` (4 710 -> 4 699 on its own) against that sibling's +253. `fixtures/surface-growth.golden` was regenerated in this edit, which moves no baseline; the hook-test surface stands at 20 245 lines against its 20 375 budget.
