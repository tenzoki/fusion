The monitor's "default wildcard bind" test case times out on a host its own `wildcardLoopbackUsable` probe declares usable
---
`hooks/lib/__tests__/monitor-warnings-panel.test.ts`, case "bin/monitor — the default wildcard bind › answers at `localhost` on both loopback families, with no MONITOR_BIND set", fails with `Test timed out in 30000ms` on this host (macOS, Darwin 25.6.0, node 25.7.0) at `c8992f13` and identically at `40a1713f`, inside and outside the Bash sandbox. The case's guard, `wildcardLoopbackUsable`, binds `::` from the vitest process and reaches it over both families, and passes here; the spawned `bin/monitor`'s listener is then never reached within the timeout. So the guard covers the state its comments describe (no Local Network permission on macOS) but not the state this host is in, where the probe's own listener is reachable and the spawned process's is not. Evidence: `npm test -- lib/__tests__/monitor-warnings-panel.test.ts` → `1 failed | 20 passed`, three runs on 2026-09-28. Acceptance: on such a host the case skips with the observed condition named, or the probe spawns and reaches a listener the way the case does, so that the suite's exit code again says something about the change under test.

Resolved: the cause was not the probe's blind spot but a reverse name lookup inside the bind. CPython's `HTTPServer.server_bind` sets `server_name` from `socket.getfqdn(host)`; measured 2026-10-07 on this host, `getfqdn('::')` took 30.07 s, `getfqdn('0.0.0.0')` 30.12 s and `getfqdn('127.0.0.1')` 0.03 s, so the wildcard monitor bound its socket and stopped listening for the case's whole 30 000 ms budget. `bin/monitor` `ReuseServer.server_bind` now calls `socketserver.TCPServer.server_bind` and records the bound host string with no lookup, and the MONITOR_BIND note carries the dated measurement and labels the 2026-08-06 "CLOSED" reading as inference. `hooks/lib/__tests__/monitor-warnings-panel.test.ts` `startMonitor` puts a `sitecustomize` stub (`RESOLVER_STUB`) on every monitor's PYTHONPATH that makes `getfqdn` and `gethostbyaddr` hang 60 s, so a lookup returning to the bind fails on any host. Red without the fix: the wildcard case and a loopback case each `Test timed out in 30000ms`. With the fix: the wildcard case passed three consecutive runs, the file 26 of 26, and a hand-started `bin/monitor test 0` with MONITOR_BIND unset wrote its URL file in 0.11 s. `wildcardLoopbackUsable` is unchanged; it guards a host with no IPv6 loopback.
