Migrate's record-field repair writes a store-prefixed citation into fields the format no longer defines
---
`skills/migrate/SKILL.md` Step 4's `rewrite_fields` repairs a record's `**Active spec/plan:**` and `**Active session history:**` values. Three things are wrong with it and none was caused by step S8, which left the pass untouched. It writes a store-prefixed, marker-exact value where the bullet documenting it claims the storeless basename with the marker wildcarded. Neither field is defined anywhere in the current format. And it edits a record whose marker may be terminal.
---
**Filed by:** coder, Kai Stalmann <ks@qantr.com>
**Cross-references:** `260910-2145_*_restore-the-per-work-item-container.md` step S8

**Evidence, measured.** A pre-v4 scratch workbench was run through the shipped Step 4 block. Its flat record's `**Active spec/plan:**` went in carrying the segment `planning/` in front of a bracket-marked basename, and came out carrying the segment `shared/planning/` in front of the same basename with the marker absorbed to the underscore form. Neither value is spelled here: a store segment is a violation this project's gates decide from the token's shape alone, with no exemption a fence or a quotation can earn, so the segments are named in words. The bullet in the same file, the one beginning "The record's path fields are reformatted to the underscore form", says the pass "rewrites the values to the storeless basename with the marker wildcarded (`260716-1910_*_plan-foo.md`)". The sed does the store *substitution* (`$t/` to `shared/$t/`) and the marker *absorb* (`[p]-` to `_p_`), and neither drops the store nor wildcards the marker. A store-prefixed citation is the violation `rules/fusion-workbench-conventions.md` `## Filename Patterns` names, and a marker-exact one dies at the next marker move.

**The second half is larger than the first.** `grep -rn 'Active spec/plan' rules/ agents/ skills/` returns `skills/migrate/SKILL.md` and nothing else at this head. Both fields went with the Turn loop; the current format defines neither, so the pass repairs a pointer no consumer reads. That does not make the repair worthless — a human reading a migrated legacy record still follows it — but it does mean the whole of `rewrite_fields` and its bullet are candidates for deletion rather than for correction, and which of the two is right is not decidable from the code.

**The third half is a rule tension, not a defect.** `reformat_one` calls `rewrite_fields` on any renamed `_<m>_circle.md`, terminal markers included, and `rules/fusion-workbench-conventions.md` `## Terminal states are history` says no header change is written into a terminal record. The defensible reading is that a format conversion is not a reconciliation, which is what the skill's own guardrail already claims. Stated so the next reader meets it in a record rather than in the code.

**Acceptance.** Either the sed writes the storeless wildcarded basename the bullet promises and the terminal-record reading is written down where the rule can be checked against it, or `rewrite_fields`, its bullet and its two call sites are deleted and the commit message says the fields they repaired are defined nowhere. Not both, and not neither.
