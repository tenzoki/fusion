The conventions let any agent dispatch the consultant for a second opinion, while the orchestrator's own table allows it only inside `/fusion:discuss`
---
`rules/fusion-workbench-conventions.md` `## Dispatching another agent` (edited at `b3c9047b`) states, for every agent, that the `consultant` is dispatched "only for a second opinion on a concept or, through `/fusion:discuss`, as the second discussion partner". `agents/orchestrator.md`'s sub-agent table (the `consultant` row, line 604 as of `64b607a9`) says the orchestrator dispatches it "Only while you are running a skill body that dispatches it: `/fusion:discuss`". The rule is emitted to the orchestrator, so the one agent that actually made the second-opinion dispatches reads two answers to "may I dispatch the consultant for a second opinion".
---
**Filed by:** reviewer, Kai Stalmann <ks@qantr.com>

**The two texts.**

- Rule, always-on: "Two bounds hold for every agent, not for the orchestrator alone: the `consultant` is no executor, so no task is routed to it, and an agent dispatches it only for a second opinion on a concept or, through `/fusion:discuss`, as the second discussion partner".
- Orchestrator table, `consultant` row, When column: "Only while you are running a skill body that dispatches it: `/fusion:discuss` makes you the first discussion partner and dispatches the consultant once per round". The bullet list at line 170 says the same: "`consultant` when a skill body you are running dispatches it — `/fusion:discuss` does, once per round".

**What the tree did.** `fusion-workbench/orchestrator-events.jsonl` holds 40 `task_start` rows with `"agent":"consultant"` stamped 2026-09-21, each with a `detail` of the form "Second opinion, step N concept", under the orchestrator session that ran plans `260920-2228_*_seven-new-defects-worked-autonomously-with-a-second-opinion-each.md` and `260921-1726_*_the-33-open-defects-of-the-11-9-1-survey-worked-autonomously-as-one-package.md`. Both plans name `**Second opinion:** consultant` on their mechanism steps. Under the orchestrator's own row those 40 dispatches are outside its stated When; under the rule they are inside it.

**How it got here.** Plan step 10 (`260921-1726_*` row 24) prescribed "the `consultant` is user-initiated only and is dispatched by no agent except through `/fusion:discuss`". The coder departed from that on purpose and said so in `b3c9047b`: that wording restates the ban `c066bfd3` deleted under `260913-0909_*_may-the-orchestrator-reach-every-tool-and-may-an-agent-dispatch-another.md`, and would have made the package's own second-opinion dispatches a violation. The departure is reasoned; what it left behind is the orchestrator row, which still carries the narrower When and was not in the step's file list.

**Fix direction.** One of the two texts moves, and the evidence favours the row: the practice the last two packages ran on, and the working-answer mechanism the directive relies on, both need a second-opinion dispatch outside `/fusion:discuss`. So the `consultant` row's When column (and the line-170 bullet) gains "or for a second opinion on a concept a plan step names", and the What column keeps "give an expert read". The other direction, narrowing the rule to the row's wording, is possible but makes 40 recorded dispatches retroactive violations and removes the second-opinion loop from both autonomous plans; if the user wants that, it is a decision, not this fix. Bytes: `agents/` has 11 572 bytes of head-room at `3d02c7fd` (plan `## Current State`); one clause fits.

**Acceptance.** `awk '/^## Dispatching another agent/,/^## Timestamps/' rules/fusion-workbench-conventions.md | grep -c 'second opinion'` and `grep -c 'second opinion' agents/orchestrator.md` both print at least `1`, and the two texts name the same two cases; `cd hooks && npm test` exits 0.
