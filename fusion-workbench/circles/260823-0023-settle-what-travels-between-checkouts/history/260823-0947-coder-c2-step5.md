## What was implemented

`skills/setup/SKILL.md` gains **Step 0i**, between Step 0h and Step 1. One detection line —
`[ -f ./fusion-workbench/.active-circle ] || find ./fusion-workbench/circles -mindepth 2 -maxdepth 2 -name '_t_circle.md' 2>/dev/null | head -1` —
collapses the whole case split into "a path printed or nothing printed". A printed path is
`MISSING-POINTER`, the name `agents/playmaker.md` already defines and `/fusion:next` already renders;
no second name was invented, and the hand-deleted-pointer case is stated as the same state rather
than a second branch. On a printed path the step names the directory and the record's first
`## Directive` line and asks once; yes writes the bare directory name into `.active-circle`, no
writes nothing.

`find … -name '_t_circle.md'` rather than the bare glob: the form is the one
`rules/fusion-workbench-conventions.md` `## Marker globs` sanctions for `find`, and it cannot abort
under zsh `nomatch` the way an unmatched glob would.

**Placement.** Before Step 2, so `bin/fusion-paths` resolves `$OUT_HISTORY` and the `SCAN_*` set
against a Circle activated on this run rather than against the pointer's absence.

**The Step 0g reconciliation.** Step 0g's sentence — that it is the only step asking the user on a
normal run — was left as it stands. Step 0i states in its own text that it asks only in the
`MISSING-POINTER` condition, which is not a normal run, so the two agree with no edit to 0g. That
was the cheaper of the two available repairs on a 1 455-byte budget, and it is also the more
accurate one: 0g's claim is about the normal run and stays true.

`rules/fusion-workbench-conventions.md` `## fusion-workbench Layout` gains `/fusion:setup` in the
pointer's writer enumeration, with the confirmed branch of this gate named as its only condition,
and the count in the same sentence moves from two activation-path writers to three.
