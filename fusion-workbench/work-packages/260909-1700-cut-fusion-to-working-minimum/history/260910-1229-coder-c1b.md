## What was done

The dispatch bound is gone in all four of its parts: the configuration leaf, the mechanism the leaf
configured, the prompts that named either, and the gates that pinned them.

**The leaf.** `orchestrator.dispatchMinutes` joins `orchestrator.maxTurns` in `RETIRED_LEAF_KEYS`
in `hooks/lib/config.ts`, in the wording and shape C1 gave the first entry. A project still
declaring it gets exactly one advisory naming the leaf, saying the setting is not read and that
there is no replacement to move it to. `GuardSettings`, `DEFAULTS`, `RawConfig` and the merge lose
their `orchestrator` container, and `explainPositiveInteger` went with the last integer leaf.

**The one thing that had to be decided rather than deleted.** With both leaves retired,
`orchestrator` holds no live setting. It stays in `CONTAINER_LEAF_RULES` as an empty leaf table,
because `validateLayer` reaches the retirement table only by walking into a container it finds
there. A key with no entry is carried through as an unknown key, undiagnosed, which is the one
outcome the retirement family exists to prevent. Retiring the container instead would have given
one advisory naming `orchestrator` and answered two different intentions with one sentence, which
is why the leaf scope was kept. Both facts are written where the code is, and pinned by four cases
in `config.test.ts`.

**The mechanism.** `rules/bounded-dispatch.md` was deleted whole: the `**Stop by:**` parameter,
the clock read between units, the per-agent unit table, the four-line bounded return and the
orchestrator's continuation section. The `IS_BOUND_AGENT` case arm and its `emit_if_exists`
came out of `bin/fusion-rules` with it. Nothing in that file turned out to be load-bearing beyond
the bound: every section is written against a stopping time that no longer reaches any dispatch.

**The prompts.** `agents/orchestrator.md` lost the Setup bullet naming `<dispatch-minutes>`, the
whole `### Bounded dispatches` section, the bounded-return test at the head of Step 3, the
bugfixer's step-2d exemption, the continuation clause in the bugfixer budget, and the three
one-line continuation clauses at the reconciler dispatch, the troubleshooting table and the curator
gate. 4 219 bytes. No other agent prompt named the bound.

**The gates.** `dispatch-bound-lint.test.ts` and `bound-agent-set.test.ts` were deleted with their
subjects: the first pinned a figure out of two prompts, the second pinned the emission audience
against `BOUND_AGENTS`, and neither has a subject left. Both goldens were regenerated, which is not
a baseline move; no growth-bound baseline was touched.

**What the bound left behind that is not the bound.** `bin/fusion-events dispatches` measures how
long each dispatch ran, and that measurement is what the ruling itself was made on. It was kept.
Two consequences were settled in code rather than by deletion: the threshold moved out of the
retired leaf into `DEFAULT_THRESHOLD_MINUTES` in `hooks/events-query.ts`, carrying the 131-pair
measurement and the break-even arithmetic that justified the figure, and `threshold_source=` now
reads `default` rather than `configured`, because no project can set it. `BOUND_AGENTS` became
`MEASURED_AGENTS`, keeping the same seven names for a new reason: they are the population the
readings taken while the bound existed covered, so a reading taken today is comparable with one
taken then. `BOUND_LANDED` became `DEFAULT_SINCE` on the same argument. Two `limit=` keys were
renamed to say what is now true: `no-bound-to-overrun` and `threshold-is-the-readings`.

**The configuration notes.** `fusion.json` and `templates/fusion.json` lost `_turnBudget` and
`_dispatchBound` and name both retirements in `_retired`; `_what`, `_override` and `_gitTracked`
were brought to a file whose one live setting is `citations.extraPaths`. This repository's own
declared keys were left exactly as they were.
