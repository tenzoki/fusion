fusion-migrate reads git's exit 128 as "no repository" and stops with exit 3 on a machine without git
---
`hooks/migrate.ts` decides "is there a repository" from one git exit code. Exit 128 of `rev-parse --show-toplevel` is git's generic fatal status, not a "no repository" answer, and a missing git binary is now a fault. A repository git refuses to open is migrated as "no repository", and a project with no repository on a machine without git cannot migrate at all.
---
**Filed by:** reviewer, Kai Stalmann <ks@qantr.com>
**Review domain:** code
**Cross-references:** `261009-1958-reviewer-git-exit-sets-26ada996.md`, `261009-1855-migrate-gitlists-has-no-maxbuffer-so-a-listing-over-1-mb-reads-as-not-a-repository.md`

**Evidence.** `hooks/migrate.ts` `## The git pass` (header) says: "'No repository' is git's 128 from `rev-parse --show-toplevel` alone; every other git call that does not exit 0 (a spawn error, ...) stops the run as a fault". `repoTop` and the `git` helper implement exactly that (`hooks/migrate.ts:141-150`, at `26ada996`). Three cases fall on the wrong side of that cut. All three were run against `git archive` extracts of `78680a11` and `26ada996` (`node hooks/dist/migrate.js survey <wb>`):

1. **A repository git refuses to open reads as "no repository".** With dubious ownership (`GIT_TEST_ASSUME_DIFFERENT_OWNER=1`, the `safe.directory` check), `rev-parse --show-toplevel` exits 128. Survey prints `derived=/filed_by/person	unknown	no-repository	4` and exits 0. The repository holds a commit with every record in it. `run` would print `reported=git	not a repository` and write `no-repository` as the derivation reason into each migrated control file. This is the class the closed issue was about (a failure read as an answer), reached through the one status the fix kept as an answer.
2. **No git binary is a fault (regression in `26ada996`).** In a plain directory (no `.git` anywhere above it) with `PATH` holding only node and `/bin`: `78680a11` exits 0 with `unknown	no-repository`; `26ada996` exits 3, `git rev-parse --show-toplevel over <wb> failed: ENOENT`. This contradicts `hooks/migrate.ts:14` ("It needs the plugin and Node and nothing else") and `bin/fusion-migrate:20` ("Plugin and Node only"). `skills/migrate/SKILL.md` Step 4 treats the same machine as `MODE=plain`. Since 13.0.0 every agent refuses an unmigrated workbench, so this machine has no way into 13.0.0. `hooks/lib/__tests__/migrate.test.ts` always puts git on `PATH` (`:22-23`), so no test covers the case.
3. **A repository with no commit yet is a fault (predates this commit).** After `git init` and no commit, `git log` exits 128 and both builds stop with exit 3. The header's own reading is "a file git does not track ... gives no person", which describes every file of an unborn branch.

**Fix direction (inference, for the implementer to check).** Let the filesystem answer whether a repository exists, and let git answer what is in it. No `.git` entry (directory or file) on the workbench's ancestor chain: no repository, git is not run. A `.git` entry while git is missing or exits 128: a fault naming git's first stderr line. `rev-parse --verify -q HEAD` exiting 1: no history, every path `untracked`. Before taking this cut, check `GIT_DIR`, `GIT_CEILING_DIRECTORIES` and linked worktrees.

**Acceptance.** Three cases in `hooks/lib/__tests__/migrate.test.ts`, each failing on `26ada996`. (a) A workbench in no repository, `PATH` without git: exit 0 and `reported=git	not a repository`. (b) A committed repository under `GIT_TEST_ASSUME_DIFFERENT_OWNER=1`: exit 3, and stderr names git's 128 line; no `no-repository` derivation. (c) A repository with no commit: survey exits 0 and every person is `unknown	untracked`. The header's sentence on "no repository" states the new cut.
