Request 80 says fusion cannot reproduce Prior's hashes, and fusion's own source tree does
---
Request 80, question 4, states: "Fusion's tree does not hold those structs, and its `state` member carries no embedded charter, so a Claude-side writer cannot produce the bytes Prior hashes." For the source tree that is false. `codec/src/prior/gojson.ts` reproduces Go's `encoding/json` output and exports `computePriorRevision` (line 452) and `computeCharterHash` (line 459), and `codec/src/prior/campaign.ts` builds the Go form with the charter embedded. The statement holds for the built codec only: `codec/dist/fusion-record.js` contains neither function. The plan's decision on the revision fields was ruled on the false premise, and Prior's answer does not admit its outcome.
