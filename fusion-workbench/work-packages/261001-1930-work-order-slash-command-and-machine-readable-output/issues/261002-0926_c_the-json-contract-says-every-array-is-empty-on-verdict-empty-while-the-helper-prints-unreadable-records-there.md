The JSON contract says every count is 0 and every array is empty on `verdict: "empty"`, but the helper prints unreadable records there
---
`hooks/order.ts` `## The JSON format` says: "On `verdict: "empty"` every count is 0, `note` is null and every array is empty." That is false for a store whose only item-form records have an unreadable `**Status:**`. `verdict` counts nodes only (`hooks/lib/work-graph.ts`, `computeWorkGraph`: `nodes.length === 0 ? "empty" : …`). Unreadable records are never nodes, so `unreadable-head` and `unreadable` can be non-zero under `verdict: "empty"`.
---
**Filed by:** reviewer, Kai Stalmann <ks@qantr.com>

**Severity:** Medium. The code is right and the contract is wrong. The header says "a consumer can be written from it". A consumer that trusts the sentence and short-circuits on `verdict == "empty"` loses the one signal `hooks/lib/work-graph.ts` keeps on purpose: it lets a reader tell "no live items" from "one live item this module could not read". Closed issue `261001-2157_*_wp-order-stops-on-verdict-empty-and-drops-the-unreadable-rows-the-helper-printed.md` was the same blind spot, in the skill.

**Evidence.** Reproduced at `d3311e73` over a scratch store holding one record with `**Status:** bogus`. The output of `--format json` was `"unreadable-head": 1`, `"verdict": "empty"`, an `"unreadable"` array naming that one scratch record. `--format markdown` prints the `**Unreadable**` list under `verdict: empty`, which is correct per its own contract (item 5, "each only when non-empty"). The TSV contract is also correct ("none when unreadable-head is 0"). The false sentence is only in the JSON section. The test case "answers verdict=empty at exit 0 … note null in JSON" in `hooks/lib/__tests__/fusion-work-order.test.ts` uses a store with no records at all, so it never meets the case.

**Acceptance.** The `## The JSON format` sentence says that on `verdict: "empty"` every count except `unreadable-head` is 0, `note` is null, `items`, `cycles` and `unresolved` are empty, and `unreadable` names any records whose head could not be read. No code change is needed. Rebuild `hooks/dist/order.d.ts`, because it carries the header, and keep `committed-dist.test.ts` green.
---
Resolved: corrected the `## The JSON format` sentence in `hooks/order.ts`: on `verdict: "empty"` every count but `unreadable-head` is 0, `note` is null, `items`, `cycles` and `unresolved` are empty, and `unreadable` names any unreadable record. No code change. `hooks/dist/order.js` and `hooks/dist/order.d.ts` were rebuilt. The `## The Markdown format` item 5 and the `bin/fusion-work-order` header make no such claim, and no test asserted it. The Evidence line now names the scratch record in words, because the citation lint read its bare name as a dangling citation.
