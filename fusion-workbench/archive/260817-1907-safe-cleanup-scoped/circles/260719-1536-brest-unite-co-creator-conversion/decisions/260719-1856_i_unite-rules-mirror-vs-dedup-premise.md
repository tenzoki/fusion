## Question

The master plan's Step 5 (dedup) assumed unite's `rules/` and `.claude/rules/` are two tracked copies of the same 12 files, to be deduplicated onto one canonical home. That premise is false, and acting on it deleted the tracked source (reverted, no commit). What is the correct handling for unite's actual structure?

## Verified ground truth (unite-co-creator)

- `RULES/` (uppercase) is the git-tracked canonical source: 11 files. Plus `rules/investigator-capture-layout.md` tracked in lowercase. On the case-insensitive macOS FS these are one physical directory (12 files).
- `.claude/rules/` is a **gitignored generated mirror** (`.gitignore:72` `.claude/*`). It is regenerated by `make mirror-rules` (`makefile:626` → `cp RULES/*.md .claude/rules/`).
- So there is **no git-tracked duplication.** Deleting "duplicates" either destroys tracked source (what the dedup did, now reverted) or deletes gitignored mirror files that `make mirror-rules` immediately restores.
- `bin/fusion-rules` reads both `./rules/` and `.claude/rules/`, so on unite it currently sees each rule twice (source + mirror).

## Consequence for the conversion

Step 5 (dedup by deletion) is **not applicable** to unite and should be dropped. The real work is Steps 6–7 (author the manifest, lean CLAUDE.md) adapted to the RULES/-source + mirror structure, then Step 8 (prove).

## The load-bearing open question

The context-reduction win depends on the mirror. Claude Code auto-loads `.claude/rules/` (all 12) in every session. Even with a perfect topic-scoped `context-manifest.yaml` on the source side, the mirror would keep always-loading all 12 rules, defeating the goal.

## Options

1. **Keep the mirror as-is; manifest scopes only the fusion-agent path.** fusion-agents get topic-scoped loading from the source root; plain Claude Code sessions keep always-loading all 12 via `.claude/rules/`. Partial win, zero change to unite's existing plain-session behaviour.
2. **Narrow the mirror to always-on rules; let the manifest + skills carry the rest.** `make mirror-rules` copies only the `[always]`-tagged rules into `.claude/rules/`; topic-scoped rules load on demand via the manifest; heavy bodies stay as skills. Full context-reduction win, but changes what plain Claude Code sessions see.
3. **Reconsider the RULES/ + mirror design entirely** in light of the manifest (larger scope; may not be worth it).

## Recommendation

Option 1 for this Circle (deliver the fusion-agent-side win without changing unite's plain-session convention), and file Option 2 as a follow-up decision if the user wants the fuller reduction. This keeps the Circle bounded and reversible. The user owns unite's convention, so this is theirs to decide.
