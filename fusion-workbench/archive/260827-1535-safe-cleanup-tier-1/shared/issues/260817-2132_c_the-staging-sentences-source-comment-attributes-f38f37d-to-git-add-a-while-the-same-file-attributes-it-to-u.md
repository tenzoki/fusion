The staging sentence's source comment attributes `f38f37d` to `git add -A`, while the same file attributes it to `-u`

---

`hooks/lib/staging-drift.ts` states the cause of `f38f37d` twice, 585 lines apart, and the two
statements name different commands. The wrong one is the docstring directly above
`stagingSentence()`, which is the text a developer reads before editing that sentence.

---

## The contradiction

`hooks/lib/staging-drift.ts:27-29` — correct:

> That shape was installed after the opposite defect (a `git add -u` over a directory staged
> three deletions whose renamed successors were untracked, `f38f37d`) …

`hooks/lib/staging-drift.ts:612-614` — wrong:

> An agent told "files were missed by `git add`" reaches for `git add -A`, and that is the
> defect on the other side — `f38f37d`, three records out of HEAD.

`f38f37d`'s own commit message settles it: "The commit before this one staged with
`git add -u fusion-workbench/shared/issues/`" and "The cause is the directory-wide `-u`."
`agents/orchestrator.md:539` says the same thing, at length, and adds the point the wrong
comment inverts: "The instruction in force at the time named `-A` alone, so the command that
did it was forbidden by nothing."

The first half of the wrong sentence is a separate and probably sound claim — an agent told
files were missed does reach for `-A`. What is wrong is the apposition that follows: `-A` is
not what produced `f38f37d`, and `-A` cannot produce that outcome at all (measured, git 2.49.0:
`git add -A <dir>` over a renamed record stages `R100`, the rename whole).

## Why it is worth correcting rather than leaving

This is a source comment, so it reaches no consuming project and costs a user nothing. It is
filed because it is load-bearing for the shipped text one function below it: the emitted
sentence rewritten in `bd2db5c` attaches the `-u` deletion mechanism to a list headed by `-A`,
which is what this comment describes. Correcting the comment and correcting the sentence are
the same reading of the same incident, and doing one without the other leaves the next editor
the same trap.

## Recommendation

Rewrite `:612-614` to keep the behavioural observation and drop the mis-attribution — for
example: an agent told files were missed reaches for `git add -A`, which over-stages; a
`git add -u` over a directory of renamed records under-commits them, which is `f38f37d`. Then
the docstring agrees with `:27-29`, with `agents/orchestrator.md:539`, and with the sentence
the function emits.

## Scope

`hooks/lib/staging-drift.ts` only. Pre-existing — the comment predates `bd2db5c` and was not
touched by it. The compiled twin `hooks/dist/lib/staging-drift.js:522-525` carries the same
text and is regenerated by `npm run build` in `hooks/`.
